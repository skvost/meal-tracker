# Meal kcal Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local web app on the Linux box that shows kcal and macros for each meal and person, and each person's average, lightest and heaviest day against a target.

**Architecture:** Two new Supabase tables hold nutrition and targets, filled by a Claude-run refresh that uses the Rohlik and Supabase MCPs.
A Python stdlib server (`kcal-app/`) reads Supabase with the service_role key, computes everything in a pure `calc` module, and serves one static page and a JSON API.

**Tech Stack:** Python 3.12 stdlib (`http.server`, `urllib.request`, `json`, `unittest`, `threading`), vanilla HTML/JS, Supabase REST (PostgREST), and a systemd user service.

**Spec:** `docs/superpowers/specs/2026-11-10-meal-kcal-design.md`

## Global Constraints

- Use only the Python standard library. Do not install pip packages or npm. Do not use a build step.
- Never commit, log, or send the service_role key to the browser. It lives only in `~/.config/meal-kcal/env` (mode 600).
- The repo root is the public GitHub Pages site. Do not commit secrets, the Tailscale IP, or personal data.
- The Supabase project id is `wooencmwsjoaguyhmsan`. The migration is additive only and must not alter existing tables, functions, or policies.
- New tables have RLS enabled and no policies.
- Port is `8765`. Bind addresses come from `BIND_ADDRS` in the env file (comma-separated, for example `127.0.0.1,<tailscale ip>`). Default is `127.0.0.1`.
- All UI text is in Czech. Use the colour tokens from `index.html` `:root` (`--bg #f6f3ec`, `--surface #fff`, `--accent #2e7d57`, `--amber #a15c07`, `--red #b93a32`, and the others).
- Missing nutrition is never counted as 0. Show it as a lower bound "≥ X kcal" and name the ingredient.
- Persons are exactly `naty` and `filip`. Starting targets are naty 1500 and filip 2400.
- Run tests with `cd kcal-app && python3 -m unittest -v`.
- Work on branch `meal-kcal`. End every commit message with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Old weeks whose `weekly_meals.meal_key` is null** (rows created before `meal_key` existed). The recipe is unknown. Show the meal with a warning and leave it out of the totals, marking the totals as incomplete. It must not crash. (Task 3 test `test_row_without_meal_key`)
2. **A `ks` ingredient whose nutrition row has `grams_per_piece` null.** This counts as missing, not as 0 g. (Task 3 test `test_piece_without_weight_is_missing`)
3. **A person who eats nothing in a category** (all amounts 0 in every meal of it). Skip that category in their lightest and heaviest day; it must not produce 0 and must not raise. (Task 3 test `test_person_absent_from_category`)
4. **Supabase paused or unreachable** (URLError, timeout, or a 5xx response). The API returns 502 with `{"error": ...}` and the page shows "Supabase je uspaný nebo nedostupný" plus the detail. Old cached numbers are never shown as if they were current. (Task 4 test `test_week_supabase_down_returns_502`)
5. **Tailscale is down at boot,** so one bind address fails. The server still serves on the addresses that work and logs a warning. (Task 4 test `test_bind_skips_unavailable_address`)

### Task 3: Calculation module

**Files:**
- Create: `kcal-app/calc.py`, `kcal-app/tests/__init__.py`, `kcal-app/tests/test_calc.py`

**Interfaces:**
- Produces:
  `compute_week(rows: list[dict], meal_ingredients: list[dict], ingredients: dict[str, dict], nutrition: dict[str, dict], targets: dict[str, int]) -> dict`
  - `rows`: `weekly_meals` rows with keys `meal_key` (which may be None), `category`, `meal_name`, `cover_name`, `total`, in display order.
  - `meal_ingredients`: rows with `meal_key`, `ingredient_key`, `naty`, `filip` (numbers).
  - `ingredients`: maps key to `{"name", "unit"}`.
  - `nutrition`: maps key to `{"kcal", "protein", "carbs", "fat", "grams_per_piece", "source", "product_id", "note", "updated_at"}`.
  - `targets`: `{"naty": int, "filip": int}`.
  - Returns:
    ```
    {"people": {p: {"target", "avg": {"kcal","protein","carbs","fat"}, "min_day", "max_day", "diff", "diff_pct", "incomplete"}},
     "meals": [{"meal_key","category","meal_name","cover_name","total","daily","missing": [names],
                "per_person": {p: {"kcal","protein","carbs","fat"}},
                "ingredients": [{"name","unit","amount": {p: num},"grams": {p: num|None},"kcal": {p: num|None},"missing": bool}]}]}
    ```
  - Rounding happens only in the output: kcal is rounded to an int, macros to 1 decimal, and `diff_pct` to an int. `PERSONS = ("naty", "filip")`.

### Task 4: Supabase client and HTTP server

**Files:**
- Create: `kcal-app/supabase_client.py`, `kcal-app/server.py`, `kcal-app/tests/test_server.py`

**Interfaces:**
- Consumes: `compute_week` from Task 3.
- Produces:
  - `class SupabaseError(Exception)`.
  - `class SupabaseClient(url: str, key: str, ttl: float = 60)`, which has:
    - `select(table: str, query: str) -> list[dict]`: a GET to `{url}/rest/v1/{table}?{query}`, cached per (table, query) for ttl seconds.
    - `set_target(person: str, kcal: int) -> None`: a PATCH to `kcal_targets?person=eq.{person}` with `{"kcal": kcal, "updated_at": <current UTC time as ISO 8601 from Python>}`
      (PostgREST does not evaluate `now()` in JSON). If PostgREST reports 0 rows updated, raise `SupabaseError`. Use `Prefer: return=minimal`, then clear the cache.
    - `clear_cache() -> None`.
    - Every network or HTTP failure raises `SupabaseError(str)`, with the PostgREST message when there is one. A 10 s timeout applies.
  - `class App(client)`, which has methods that return `(status: int, body: dict)`:
    - `week(start: str | None)`: returns the `compute_week` result plus `"weeks": [desc list]` and `"week": start_used`. With no data at all, it returns 200 with `{"weeks": [], ...}`.
    - `ingredients()`: returns `{"ingredients": [{"key","name","unit","kcal","protein","carbs","fat","grams_per_piece","source","product_id","product_name","note","updated_at","missing"}]}`, with missing ones first.
    - `put_target(person: str, raw_body: bytes)`.
  - `load_config(path: str) -> dict` parses `KEY=VALUE` lines. Missing `SUPABASE_URL` or `SUPABASE_SERVICE_KEY` raises `SystemExit("…missing SUPABASE_SERVICE_KEY in <path>")`.
  - `serve(app: App, addrs: list[str], port: int) -> list[ThreadingHTTPServer]` starts one server thread per address. An address that fails to bind is logged and skipped. If none bind, it raises SystemExit.
  - Routes:
    - `GET /` serves `static/index.html`.
    - `GET /api/week[?start=YYYY-MM-DD]`.
    - `GET /api/ingredients`.
    - `PUT /api/targets/{naty|filip}`.
    - Anything else returns 404 as JSON.
- Supabase queries the App makes:
  - `weekly_meals`: `select=week_start` to list the weeks, then `select=meal_key,category,meal_name,cover_name,total&week_start=eq.{w}&order=id`.
  - `meal_ingredients`: `select=*`.
  - `ingredients`: `select=key,name,unit`.
  - `ingredient_nutrition`: `select=*`.
  - `products`: `select=product_id,name&preferred=is.true`.
  - `kcal_targets`: `select=person,kcal`.
